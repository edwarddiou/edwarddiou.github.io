Master's Thesis 碩士論文

G3-RAG

Knowledge Graph × RAG / Multi-step Reasoning / Multi-hop QA

2023.07 — 2025.02 M.S. thesis · oral defense passed, journal submission in progress 碩士論文 · 已通過口試，期刊投稿中

G3-RAG is my M.S. thesis research, proposing a Retrieval-Augmented Generation (RAG) architecture built around knowledge graphs to address the information-loss problem that LLMs face on long inputs. Through relation extraction it builds a structured graph, combines it with graph retrieval and a multi-round reasoning mechanism, and lets the model converge on the answer step-by-step on multi-hop tasks —— rather than throwing everything into one long context where the critical signal gets diluted.

G3-RAG 是我的碩士論文研究，提出一個以知識圖譜為核心的 檢索增強生成（RAG）架構，解決大型語言模型在處理長文本時 常見的資訊遺失問題。透過關係抽取建立結構化圖譜、 搭配圖檢索與多輪推理機制， 讓模型在多跳推理任務中能逐步逼近答案， 而不是在一次性的長 context 裡讓關鍵訊號被稀釋掉。

Abstract 摘要

This research presents a retrieval-augmented generation model called G3-RAG, designed to address the issue of information loss commonly encountered by large language models (LLMs) when processing long texts. Existing RAG models often miss critical information in lengthy documents, leading to inaccurate results. G3-RAG enhances the processing of comprehensive information and the integration of multi-source knowledge by constructing a structured knowledge graph using relation extraction techniques and integrating graph-based retrieval methods.

The research also introduces a special technique that enables multiple rounds of reasoning to gradually find answers, particularly excelling in multi-hop reasoning tasks. Additionally, G3-RAG utilizes a special technique to enhance memory during the reasoning process. Experimental results show that G3-RAG can retrieve more precise information and make more accurate inferences when dealing with complex problems, significantly improving the overall performance of LLMs.

本研究提出了一種檢索增強生成（RAG）模型 G3-RAG， 旨在解決大型語言模型（LLM）在處理長文本時常見的資訊遺失問題。 現有的 RAG 模型在處理長篇文檔時，往往會遺漏關鍵資訊，導致結果不準確。 G3-RAG 通過構建基於關係抽取技術的結構化知識圖譜， 並結合圖檢索方法， 提升對全面資訊的處理能力及多源知識的整合效果。

本研究還引入了一種特殊技術，能夠進行多輪推理， 逐步尋找答案，特別適用於多跳推理任務。 此外，G3-RAG 採用特殊技術來增強推理過程中的記憶能力。 實驗結果表明，G3-RAG 在處理複雜問題時， 能夠檢索到更精準的信息並做出更準確的推論， 顯著提升 LLM 的整體性能。

Why this architecture 為什麼需要這個架構

The problem isn't "the LLM didn't see the data" — it's "the LLM saw it, but couldn't pick out what mattered". Long-context LLMs and vanilla RAG each have structural weaknesses on multi-hop reasoning tasks — G3-RAG's design targets those weaknesses one by one.

問題不是「LLM 沒看到資料」，而是「LLM 看到了，但抓不到關鍵」。 長 context LLM 跟 vanilla RAG 在多跳推理任務上各自有結構性的弱點 —— G3-RAG 的設計就是針對這幾個弱點各個對應。

  • Long-context info loss 長 context 資訊遺失 Dumping a full document into a long-context LLM doesn't solve the problem — attention to the middle of long sequences decays (lost in the middle), and the critical signal gets diluted by redundant text. "In the context" is not the same as "actually used". 把整份文件丟進 LLM 的長 context 不能解決問題 —— LLM 對長序列中段內容的 attention 會衰減（lost in the middle）， 關鍵訊號被冗餘文本稀釋。 資訊「在 context 裡」不等於「會被用到」。
  • Naive RAG can't handle multi-hop Naive RAG 解不了多跳 Traditional RAG retrieves top-k chunks in one shot — fine when the answer lives in a single paragraph, but multi-hop questions need cross-passage chaining (A → B → C). A single retrieval call can't reach that cross-paragraph topology. 傳統 RAG 一次 retrieval 抓 top-k chunks， 適合答案直接落在單一段落的問題； 但多跳問題需要跨段資訊串接（A→B→C 的鏈式推理）， 單次 retrieval 抓不到這種跨段拓撲。
  • Flat chunks lack structure 平面 chunk 缺結構 Chunk-based retrieval slices long text into flat paragraphs and severs the relations between entities (who connects to whom, under what conditions). For multi-hop reasoning the retrieval signal itself needs to be structured, so the LLM can advance along the relation chain. chunk-based retrieval 把長文本切成平面段落， 實體之間的關係（誰跟誰相關、什麼條件下成立）被切斷。 做多跳推理時，retrieval 訊號本身就要是結構化的， 才能讓 LLM 沿著關係鏈推進。
  • Multi-round needs memory 多輪推理需要記憶 Single retrieval → single generation forces the model to answer from one shot of clues. Multi-hop questions need a recursive pattern: derive an intermediate conclusion, then use that conclusion to retrieve again. Without cross-round memory, round two isn't any smarter than round one — memory is what makes "multi-round" actually beat "single-round". 單輪 retrieval → 單輪生成，模型只能基於一次的線索作答； 但多跳問題需要「先得到中間結論、再用中間結論去 retrieval」這種遞迴模式。 沒有跨輪記憶，第二輪 retrieval 不會比第一輪更聰明 —— 記憶機制是讓「多輪」真正比「單輪」強的關鍵。

G3-RAG maps these four weaknesses to concrete design choices: relation extraction to build the knowledge graph fixes the flat-structure problem; graph retrieval makes multi-hop chains locatable; multi-round reasoning addresses long-context dilution; memory enhancement lets multiple rounds accumulate toward convergence. The architecture diagram in the next section is the concrete implementation of these choices.

G3-RAG 把這四個弱點對應到具體的設計選擇： 關係抽取建構知識圖譜解決平面結構問題、 圖檢索讓多跳鏈式推理可定位、 多輪推理解決長 context 訊號稀釋、 記憶增強讓多輪可累積收斂。 下一節的架構圖就是這些設計選擇的具體實作。

System architecture 系統架構

The core flow: use relation extraction to turn long text into a structured knowledge graph, use graph retrieval to find the question-relevant subgraph, and let the LLM absorb the graph signal across multiple rounds of reasoning to converge on the answer.

G3-RAG 的核心流程：先用關係抽取把長文本轉成結構化知識圖譜， 再透過圖檢索方法找出與問題相關的子圖， 最後讓 LLM 在多輪推理中逐步吸收圖譜訊號並收斂到答案。
